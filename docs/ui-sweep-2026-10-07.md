## Guidance used

- [Material adaptive window-size guidance](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes):
  assess available window width and compact landscape height, rather than infer
  layout from a device name.
- [Apple design tips](https://developer.apple.com/design/tips/): aligned
  controls, readable spacing, content fitting the window, and comfortable touch
  areas.
- [GOV.UK layout guidance](https://design-system.service.gov.uk/styles/layout/):
  narrow-screen structure and bounded prose lengths. Docs paragraphs now have a
  `75ch` maximum; this is a layout aid, not an exact character count for a
  proportional font.
- [WCAG 2.2 target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html):
  24 CSS pixels or the criterion's permitted exceptions. The site uses 44 CSS
  pixels as its comfortable-control target; inline prose links are treated
  separately. This sweep is not a full WCAG conformance assessment.

## Limits

Follow-up from the owner's dev preview: at 641–760px, the intermediate docs
navigation grid stretched short groups' links to match the longest group (about
143px high at 701px). Minimum-target and overflow checks did not detect this
visual defect. That range now uses the same compact horizontal navigation row as
narrower screens. Regression coverage includes 640, 641, 700, 760 and 761px, and
checks that compact navigation stays on one row with normal button heights.

Another dev-preview follow-up found that generic link-hover colors could
override button-owned foregrounds, including the docs primary action and linked
form actions. Lower-specificity hover defaults now preserve those foregrounds in
light and themed controls while plain links retain their hover colors. Docs
primary blues were adjusted so white text measures approximately 4.83:1 normally
and 6.01:1 on hover. The browser regression checks settled hover colors for
representative actions and both plain-link themes, plus both docs contrast
states.

The sweep combined native desktop WebView previews, viewport simulation,
Chromium regressions and source review. It did not test physical touch devices,
every browser/assistive-technology combination, every account-data permutation,
or an actual third-party account-creation/consent screen. External PDS screens
remain outside this site's UI control. A populated signup-host list is exercised
with simulated host responses in the browser suite; the isolated local database
also exercised the no-host-results state.

The relationship-confirmation and app-directory failure-detail templates were
covered by source/layout review, not a populated browser fixture in this sweep.
Production smoke tests remain a release-time step.

## Release-review follow-ups

The release browser check exposed a native details toggle race in the app
filter. Closing the element synchronously as well as its signal prevents Escape
from leaving it open before the queued toggle event runs. Independent review
also restored mouse-opened filter Escape handling, guarded against active modal
dialogs, and added a body-focus mouse regression for each filter owner.

Desktop docs navigation now scrolls its sidebar vertically to reveal the active
page without scrolling the document. A 1440×700 browser check covers the API
reference link. Inline admin contact links preserve prose line height, generic
themed hover defaults have lower specificity than component colors, file upload
rings use focus-visible, and the banner thumbnail no longer duplicates the
Replace input's tab stop. Admin note actions align to the input. Enter in the
URL override saves its draft through an isolated form without submitting the
profile. The already-loaded docs-script path also initializes the TOC
disclosure.

Source audit confirmed the static host filter script loads only on `/hosts`, not
on island-owned app or signup menus. Portaled modal styles use standalone
classes; the theme rules remain available for body-level themes, and current
page sources do not apply an ancestor-only `dark-phase` class.

All docs code/table containers intentionally retain a named keyboard stop even
when they fit. The keyboard checks require scrolling only when content actually
overflows; they do not establish that every table overflows at a tested width.
This conservative fallback preserves keyboard access without JavaScript.

The final theme audit covers all tracked runtime sources, including `client.ts`,
`routes/_app.tsx`, islands, and static scripts: none adds `dark-phase` to body,
html or any other element. That string occurs only in styles, test fixtures and
this report. `routes/_app.tsx` explicitly declares the site light-only and sets
`color-scheme: light`. The dark selectors are dormant compatibility rules, not a
live theme path. No markup uses `inline-form` in this repository; the explicit
inline modifier applies to the admin contact links. Hidden dialog markup no
longer suppresses filter Escape, and the sidebar assertion also bounds the
active link against the viewport.
